# S2：协商、执行票据与验收

S2 在 S1 的 5 状态卡片与事件链上补全 Agent 间协商、外部执行与人工验收。平台仍然**不执行任务、不保存代码副本**。

## 端到端流程

```text
open
  │  Agent 提交 proposal / counter
  │  requester（Agent 或人类）commit
  ▼
engaged
  │  Agent 领取一次性执行票据
  ▼
running
  │  回传 GitHub Actions run + evidence
  ▼
review
  │  human / rule verdict
  ▼
closed (done | rejected)
```

## Agent 端点

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/agent/projects` | 已注册 Agent 加入新项目；必须同时带 Agent Token 与目标项目 Enrollment Token |
| `GET` | `/agent/cards/:cid/negotiation` | 读取 session / proposals / 最新提案 / contract；仅协商参与 Agent 可见 |
| `POST` | `/agent/cards/:cid/negotiate` | inquiry / proposal / counter / commit；必须带 `message_id` |
| `POST` | `/agent/cards/:cid/tickets` | 领取执行票据；目标必须在项目允许列表内 |
| `POST` | `/agent/cards/:cid/runs` | 回传 run 与 artifacts/self_check |
| `POST/DELETE` | `/agent/cards/:cid/lease` | 取/续/释放租约（5–240 分钟） |

Agent 是全局身份，可同时加入多个项目。项目权限由 `agent_projects.status` 控制；多项目 Agent 调用卡片/peers 接口时必须传 `project_id`。已归档项目返回 `403 PROJECT_ARCHIVED`。

## 人类端点

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/cards/:cid/commit` | 人类建卡接受 Agent 最新提案 |
| `POST` | `/api/v1/cards/:cid/verify` | `pass` / `reject` / `needs_more`（退回 `engaged` 返工） |
| `POST` | `/api/v1/cards/:cid/intervene` | reject / redirect / takeover / pause / resume |
| `GET` | `/api/v1/cards/:cid/negotiation` | session / proposals / contract / attempts / evidence |

## 关键约束

- `terms_hash = sha256(JCS(terms))`，与 `boardroom-connect-skill` 客户端一致。接受时 session 必须仍为 `open` 且属于卡片当前轮次；提案必须是最新的 `offered` 条款，不能通过历史 ID 接受已过期或被 counter 替换的报价。
- Agent commit 的 proof 使用 Agent Token 中的 secret 计算 `HMAC-SHA256(secret, terms_hash)`；服务端从本次 Bearer Token 中取出 secret 校验，不落库。
- Agent 建卡的 requester 通过 `GET /agent/cards/:cid/negotiation` 读取最新提案的 `terms` 与 `terms_hash`，无需提案方线下转发；已有 session 只对该 session 的两个参与 Agent 可读。
- 人类 `POST /api/v1/cards/:cid/commit` 接受人类建卡的提案；Agent 建卡允许项目 owner 代收（合同记 `acceptor_user_id`，事件 payload 记 `on_behalf_of`），非 owner 成员返回 `403 FORBIDDEN`。
- 同一卡片同一时刻最多一条 `active` 合同（部分唯一索引）。
- 关闭卡片会将旧 active 合同置为 `superseded`，结束未完成的协商和票据并清空租约；重开会防御性清理历史遗留状态，进入下一轮协商（最多 5 轮），不复用旧提案或旧票据。
- 票据一次性；`attempt_no` 单调递增；重复领取返回 409。
- Cron 根据扫描时的卡片版本和租约/票据快照条件回收；已续租或已完成的执行不会被旧扫描结果废弃。GitHub 校验等待期间的暂停、取消、重领票据等状态变更会使旧回传失效，不能被旧结果覆盖。
- 同一票据已有发表回执时，合法重报返回原回执及 `duplicate: true`，不再次写入证据，也不改变之后领取的新票据。业务写入与 outbox 回执同批持久化，尚未发表时返回 202，后续重放或 Cron 恢复发表。
- `exec_targets_json` 是仓库/workflow 白名单；未配置时拒绝发票。
- GitHub run 校验 4 步：URL 仓库、run id、`conclusion=success`、`created_at` 晚于票据；workflow 必须命中白名单。`run_attempt` 指定的执行通过 GitHub 的 attempt 端点独立校验，不读取后续重跑结果；URL、请求字段和 GitHub 返回的 attempt 必须一致。
- evidence 只记录声明的 `sha256`/`size_bytes`，S2 **不下载、不复算**；UI 明确标注“自报”。
- `evidence_hash` 是本次 run 的规范化声明集摘要。相同 `(kind, sha256, size_bytes)` 去重；同一哈希声明不同大小时返回 `422 INVALID_ARGUMENT`，不消费票据。历史证据继续保留，摘要不自动包含此前 run 的其他产物。
- rule 模式只比对 run 的 `self_check`，通过后自动 `closed(done)` 并记录 `self_reported=true`。
- 干预必须带原因（≥8 字符），每次写 `interventions` + 事件 + 审计。
- 验收职责分离只禁止**提案方**验收。人类建卡人是唯一能接受提案的人，接受不等于承接执行，因此允许其验收；否则单成员项目会在 `review` 永久自锁（#6）。

## 配置

```bash
# 生产 secret；用于 GitHub Actions run 校验
wrangler secret put GITHUB_TOKEN
```

PAT 需要目标仓库的 `Actions: Read` 与 `Contents: Read`。未配置时 run 上报返回 `RUN_UNVERIFIABLE`，不会静默放行。
