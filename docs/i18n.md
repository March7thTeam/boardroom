# 多语言（i18n）

S1 只预留接口与基础覆盖，不引入第三方 i18n 依赖。后端与前端各有一套同构的「扁平 key + `{name}` 插值」实现。

## 后端

```
src/i18n/en.ts       # 源字典
src/i18n/zh.ts       # 中文，类型强制与 en 对齐
src/i18n/index.ts    # LOCALES / getTranslator / parseAcceptLanguage
src/middleware/locale.ts
src/routes/locale.ts
```

- 解析顺序：`?lang=` → `X-Locale` → `lang` cookie → `Accept-Language` → `zh`。
- 中间件把 `locale` / `t` 放入 Hono context；`app.onError` 用 `error.code` 查 `error.*` key，查不到则保留原 message。
- 接口：
  - `GET /api/v1/locale` → `{ locale, default_locale, locales, labels }`
  - `POST /api/v1/locale` `{ locale }` → 写 `lang` cookie
  - `GET /language/:code?next=/` → 写 cookie 并重定向（浏览器入口）
- 响应带 `Vary: Accept-Language`。

## 前端

```
apps/web/src/i18n/en.ts
apps/web/src/i18n/zh.ts
apps/web/src/i18n/core.ts    # 无 React 依赖，api.ts 也用它读 locale
apps/web/src/i18n/index.tsx  # I18nProvider / useI18n
```

- `I18nProvider` 在 `main.tsx` 包裹 `<App />`。
- locale 持久化在 `localStorage["boardroom.locale"]`，首次访问按 `navigator.language` 推断，默认 `zh`。
- `api.ts` 发送 `Accept-Language`；SSE 用 `?lang=` 查询参数。
- 顶栏语言选择器切换后立即更新 shell、看板列、卡片状态/结果、连接状态等已提取文案。

## 增加文案

1. 在 `en.ts` 加 key（源字典）。
2. 在 `zh.ts` 加同名 key；类型检查会强制对齐。
3. 组件里用 `useI18n()` 的 `t("your.key", { name })`。
4. 后端错误文案用 `error.<CODE>` 命名，`translateErrorCode` 会自动匹配。
